# UI — 嵌入式触摸屏图形界面中间件

用 C99 编写的嵌入式图形界面中间件，核心是脏矩形增量刷新：应用登记发生变化的矩形区域，库把这些区域按行切片绘制到行缓冲，再交给使用方提供的后端送屏。未变化的区域不重绘，绘制与搬运可以重叠进行。

适用于 RAM 与 Flash 有限的 MCU：不使用动态内存，不依赖操作系统，全部缓冲静态分配且容量可配置。

支持 RGB565、BGR565、RGB888、ARGB8888 四种像素格式，由 `UI_COLOR_FMT` 选择；库内颜色统一为 `ui_color_t`，混色与渐变随所选格式计算，切换格式不需要修改库代码。

库实现与硬件无关的部分：对象、链与层级，命中测试，触摸事件状态机，图元绘制与裁剪，动画，字模缓存，以及滑块、按钮、表格、滚动视图等组件。显示屏输出、触摸采样、字模与图片数据的读取由使用方通过回调接入，接口见第 6 节。

代码规模 13,407 行（含注释），其中有效代码 8,825 行。

## 1. 渲染流程

1. 应用修改对象状态后调用 `ui_dirty_mark(x0, y0, x1, y1)` 登记脏矩形。矩形进入表中时做包含判断与合并；表满后若合并代价超过阈值（约半屏像素），退化为整屏标脏，使耗时可控。
2. 每帧开始时调用 `ui_dirty_frame_begin()`，把上一帧的脏区补入本帧的表。双缓冲需要这一步，单缓冲下该函数不做任何事。
3. `ui_render_slice()` 从表中取出最靠上的一块，按「该块完整宽度 × 行缓冲可容纳的行数」切片，得到一行范围与列范围。
4. 库调用场景绘制回调 `scene()` 把这一片重画一遍。图元只写当前行缓冲，绘制范围被限制在该片列范围与当前裁剪区内。
5. 画满一片后，库通过后端回调 `start(chunk)` 把这片交给硬件；`chunk` 给出起点、行数、每行像素数与像素首地址。
6. 两块行缓冲交替使用：一片交给硬件期间，CPU 在另一块上绘制下一片。`ui_render_slice()` 不阻塞，`ui_render_idle()` 为真表示本帧已全部送出且硬件搬运完成。

## 2. 缓冲模式

库不区分单缓冲与双缓冲，两者差异只体现在一项配置以及是否翻页。

| 项目 | 单缓冲 | 双缓冲 |
| --- | --- | --- |
| `UI_DIRTY_KEEP_PREV` | 0 | 1 |
| 帧缓存数量 | 1 | 2 |
| 每帧推送内容 | 本帧脏区 | 本帧脏区 ∪ 上一帧脏区 |
| 翻页 | 不需要 | 消隐期切换显示地址 |
| 显示效果 | 刷新期间可能出现局部撕裂 | 无撕裂 |
| 额外 RAM | — | 一块帧缓存 |

双缓冲下，后台帧缓存欠的是「自它上次显示以来」的全部变化，因此每帧必须无条件调用 `ui_dirty_frame_begin()`，即使该帧没有任何脏矩形。单缓冲下该调用不产生额外推送。

若后端使用帧缓存，开机时应把整屏完整绘制进每一块帧缓存（单缓冲只需一次），否则首次翻页时，静态内容可能只存在于其中一块。

## 3. 颜色格式

四种格式由 `ui_config.h` 的 `UI_COLOR_FMT` 选择：

| 宏 | 位宽 | 排列 |
| --- | --- | --- |
| `UI_COLOR_FMT_RGB565` | 16 | R5 G6 B5 |
| `UI_COLOR_FMT_BGR565` | 16 | B5 G6 R5（R/B 交换） |
| `UI_COLOR_FMT_RGB888` | 32 | 32 位容器，实际为 R8 G8 B8，高 8 位为 0 |
| `UI_COLOR_FMT_ARGB8888` | 32 | A8 R8 G8 B8，A 分量固定为 0xFF |

- 颜色一律用 `UI_RGB(r, g, b)` 书写，按当前格式打包，r / g / b 取 0～255。
- 库内颜色与像素的类型为 `ui_color_t`：16 位档是 `uint16_t`，32 位档是 `uint32_t`。行缓冲、图片像素、透明键色、各图元的颜色字段都用这个类型。
- `UI_PIXEL_BYTES` 给出单像素字节数（2 或 4），供外部换算帧缓存大小与行偏移。
- 混色与渐变调用 `ui_color_blend(bg, fg, alpha)` 与 `ui_color_lerp(c0, c1, t, tmax)`，格式相关的位运算收在实现里。外部绘制代码不要自行编写 565 位运算，否则切换格式时会出错。
- ARGB8888 的 alpha 分量在混色结果中固定写 0xFF。库不使用逐像素 alpha，半透明由绘制调用中的 `alpha` 参数控制。

切换格式时库代码无需改动，但以下外部内容必须同步：

- 显示控制器的像素格式、帧缓存大小与行偏移、异步搬运的目标格式；
- 片外图片与图标的像素数据，按新格式重新转换；
- 透明键色的取值，键色是按格式打包后的数值。

## 5. 资源占用

| 项目 | 计算方式 | 说明 |
| --- | --- | --- |
| 行缓冲（2 块） | `2 × 20 × MAX_W × sizeof(ui_color_t)` | 屏宽 1024 时：16 位格式 80 KB，32 位格式 160 KB |
| 字模缓存 | `UI_FONT_CACHE_NUM × (8 + UI_GLYPH_MAX_BYTES)` | 32 槽约 72 KB，可降至 4～8 |
| 脏矩形表 | `UI_DIRTY_MAX_CAP × 8 B` | 默认 512 B |
| 每帧任务表 | `UI_MODULE_TASK_MAX × 12 B` | 默认 384 B |
| 触点数组 | `UI_EVENT_TOUCH_MAX × 13 B` | 默认 130 B |

以屏宽 1024、字模缓存 32 槽计：16 位格式合计约 153 KB，32 位格式约 233 KB。帧缓存不计在内：是否需要、放在何处（片内或片外）由后端决定；若使用，另需 `W × H × UI_PIXEL_BYTES × 缓冲数`。

`MAX_W` / `MAX_H` 必须等于实际屏幕分辨率。小于实际尺寸时，`ui_dirty_set_screen()` 会把参数夹回上限，超出部分不会被标脏；大于实际尺寸时，常规标脏仍按实际尺寸裁剪，但脏矩形表溢出后退化为整屏标脏的路径直接使用 `MAX_W` / `MAX_H`，会标出屏外区域，切出的片宽于屏幕，后端按行偏移写入时错位。

对硬件的要求：

- 显示屏及其控制器，像素格式与 `UI_COLOR_FMT` 一致，行偏移与帧缓存大小按 `UI_PIXEL_BYTES` 计算；
- 搬运手段：能接收一块矩形区域的像素。若可异步（例如 DMA），`busy()` 反映搬运状态，绘制与搬运即可重叠；只能同步搬运时，`busy()` 恒返回 0，仍可正常运行；
- 1 ms 定时器，作为动画时基；
- 触摸驱动，单次可返回触点数组及每点的跟踪 id；
- 可选：字库与图片的存放介质。不使用片外数据时，可退回内置点阵与片内图片。

## 6. 移植

### 6.1 编译接入

1. 将 `UI/` 目录加入头文件搜索路径。库内部使用 `"./ui_xxx/..."` 形式的相对包含，包含根必须是 `UI` 这一级。
2. 将 `UI/*/` 下全部 `.c` 加入工程。`ui_font_data.c` 提供内置兜底字模，不可删除。
3. 语言标准 C99 及以上。

### 6.2 需要实现的回调

以下六处由使用方实现，库只定义签名。

| 接缝 | 需要实现 | 挂接方式 |
| --- | --- | --- |
| 推屏后端 | `uint8_t busy(void)`，1 表示上一片仍在搬运<br>`void start(const ui_row_chunk_t *chunk)`，把一片交给硬件 | `ui_render_init(&dev, scene)` |
| 场景绘制 | `void scene(void)`，把当前片整屏绘制一遍：先铺底色，再从根层级按 z 序派发 | 同上，第二个参数 |
| 触摸输入 | 每帧读取驱动并换算为屏幕坐标，调用 `ui_event_feed(pts, count, ms)` | 主循环调用 |
| 字库 | 读点阵函数，签名同 `ui_hz_glyph_fn_t`：<br>`uint8_t fn(uint8_t font_id, const uint8_t *code, uint16_t size, uint8_t *buf, ui_glyph_t *glyph)` | `ui_font_set_reader(fn)`；文字对象的 `hz_glyph_fn` 填 `ui_font_glyph` |
| 图片取行 | `uint8_t row(uint8_t img_id, int16_t y, int16_t c0, int16_t c1, ui_color_t *buf)` | `ui_image_para_t::row_fn`；片内点阵可直接填 `pixels` |
| 时基 | 在 1 ms 定时器回调中调用 `ui_anim_tick(NULL)` | 定时器回调 |

`start()` 收到的 `ui_row_chunk_t` 中，`buf` 是 `ui_color_t *`，内容为当前格式的像素，行优先紧密排列；`pixels_per_row` 是本片有效宽度，不等于屏幕宽度；目标位置由 `start_x` / `start_y` 确定。`busy()` 的语义必须是「上一片是否仍在搬运」，返回恒定 0 也可运行。

### 6.3 注意事项

1. 触点标识：`ui_touch_point_t::id` 应填写驱动提供的触点跟踪号，不得使用数组下标。部分驱动仅保证前 n 个槽位有效，触点抬起后其余触点前移，下标与物理触点之间不存在稳定对应关系，点击事件将无法合成。
2. 字模位序：片外字库通常按字节内高位在左存储，库要求低位在左。读点阵函数应完成位序转换，未转换时字形显示为碎片状。
3. 图标像素格式：片外图标的像素数据须与 `UI_COLOR_FMT` 一致。透明像素以键色实现，键色数值随格式变化，应与转换工具使用相同取值。

### 6.4 初始化顺序

```c
lcd_init();                                   /* 使用方：屏控制器与后端就绪 */
ui_dirty_set_screen(width, height);           /* 必须早于第一次标脏 */

font_port_init();                             /* 使用方：内部调用 ui_font_set_reader() */
page_init();                                  /* 使用方：建立页面对象与层级 */

timer_set_callback(ui_anim_tick, NULL);       /* 1 ms 周期 */
touch_port_init();                            /* 使用方 */

ui_event_set_level(root);                     /* 指定事件派发层级 */
ui_render_init(&flush_dev, scene);            /* 接上后端与场景绘制 */
boot_sync();                                  /* 使用方：整屏绘制进每块帧缓存 */
```

字库初始化必须早于首帧整屏绘制：首帧绘制完成后该区域不再属于脏区，此后才就绪的字模不会被补画。

### 6.5 主循环

```c
while (1)
{
    if (frame_can_start())          /* 使用方：后台缓冲可用；单缓冲可恒为真 */
    {
        ui_dirty_frame_begin();     /* 每帧无条件调用 */
        ui_module_task_all();       /* 组件每帧任务 */
        touch_poll();               /* 使用方：读触摸并调用 ui_event_feed() */
    }

    ui_render_slice();              /* 取一片、画一片、提交一片；不阻塞 */

    if (ui_render_idle())           /* 脏区取完、片已提交、硬件搬运完成 */
    {
        frame_present();            /* 使用方：请求翻页；单缓冲可省略 */
    }
}
```

## 7. 配置项

| 宏 | 作用 | 默认值 |
| --- | --- | --- |
| `UI_COLOR_FMT` | 像素格式，取值见第 3 节 | `UI_COLOR_FMT_RGB565` |
| `MAX_W` / `MAX_H` | 屏幕分辨率，须与实际一致 | 1024 / 600 |

## 8. 使用注意

1. 库不检测对象外观变化。任何影响显示的修改之后都必须调用 `ui_dirty_mark()`，否则不会重画。
2. 双缓冲下每帧必须调用 `ui_dirty_frame_begin()`，即使该帧没有产生脏矩形。
3. `ui_dirty_set_screen()` 应在第一次标脏前调用，传入尺寸会被夹到 `MAX_W` / `MAX_H`。
4. 触摸采样应放在帧开始之后、`ui_render_slice()` 之前。回调中标的脏区落在当前后台缓冲上，位置不当会导致延迟一帧或丢失。
5. 必须等 `ui_render_idle()` 为真才翻页，否则最后一片仍在搬运时会翻出缺块的画面。
6. `MAX_W` / `MAX_H` 必须等于实际分辨率，原因见第 5 节。
7. `UI_FONT_CACHE_NUM` 必须为 2 的幂，内部以 `& (N-1)` 取模，否则槽位错乱。
8. 库不是线程安全的。标脏、事件派发与翻页请求应在主循环中完成；中断中只修改翻页请求标志。
9. 字库、图标与页面对象应在首帧整屏绘制之前准备完毕。
10. 切换 `UI_COLOR_FMT` 后需重新核算 RAM：行缓冲与帧缓存按 `sizeof(ui_color_t)` 变化，32 位档是 16 位档的两倍。
